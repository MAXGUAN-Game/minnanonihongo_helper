# v1.1 更新与回退

这版增加自己说录音、0～100 表达评分、90 天录音历史、逐课教材原声与统一音频控制。AI 新回复先朗读，点“显示原文”才展开。表达评分只评确认后的文字，不是发音评分。

教材文件从三A官方 HTTPS 地址直接播放，Git 和源码包只包含音轨清单；原声列表按官方顺序显示，不猜测每条音轨的题型。

官方来源：[第二版初级Ⅰ](https://www.3anet.co.jp/np/resrcs/230020/) · [第二版初级Ⅱ](https://www.3anet.co.jp/np/resrcs/240020/)。清单可用 `node scripts/refresh-textbook-audio.mjs` 手动更新；只读取公开播放列表，不下载 MP3。源站短暂不可用时，已核对条目保存在被 Git 忽略的 `test-results/textbook-audio-metadata.json`，之后用 `--resume` 继续。

## 发布前

1. 在本地检查本次提交、测试和构建结果，记录确定的 Git 提交号。
2. 目标仅为新服务器 `8.133.242.232`；不操作有其他网站的旧服务器。
3. 保留 `/opt/nihongo/.env`、`server-data/`、当前 `deploy/Caddyfile` 与 Docker 证书卷。服务器的 Caddyfile 已按 IP HTTPS 配置，不能用仓库中的域名模板覆盖。
4. 从网站导出学习记录。涉及数据结构调整时，先停 app，再私密备份完整 `server-data/` 和 `.env`；运行中的 SQLite 不能只复制一个主数据库文件，WAL 也可能保存未合并的数据。

## 更新

这次的发布标签是 `v1.1.0`。第一次准备独立源码目录时，在服务器执行（已有目录会复用；有未提交改动时先处理，不能强制覆盖）：

```bash
if [ -d /opt/nihongo-src/.git ]; then
  sudo git -C /opt/nihongo-src fetch origin tag v1.1.0
else
  sudo git clone --branch v1.1.0 https://github.com/MAXGUAN-Game/minnanonihongo_helper.git /opt/nihongo-src
fi
sudo git -C /opt/nihongo-src checkout --detach v1.1.0
sudo docker build -t nihongo-web:v1.1.0 /opt/nihongo-src
```

若 GitHub 网络或私有仓库登录不可用，可将本次源码包解压到另一个独立目录构建。不要解压覆盖 `/opt/nihongo`。构建时使用现有缓存与网络，不需要重新运行网站配置向导。

1. 在独立源码目录（例如 `/opt/nihongo-src`）取出要发布的提交，构建镜像 `nihongo-web:<提交号>`。构建成功前，现有应用继续运行。
2. 记录当前 app 容器实际使用的镜像 ID，并为它保留明确的回退标签。仅记录 Git 提交号不足以保留原来的构建产物。
3. 将新镜像标记为现有运行配置使用的 `nihongo-web:local`。在原 `/opt/nihongo` 运行：

   ```bash
   sudo docker compose -f compose.yaml up -d --no-build --pull never --wait --wait-timeout 120 app
   ```

4. 检查应用健康状态、HTTPS 登录、原学习记录及新功能。Caddy、运行目录、登录信息和录音/学习数据保持原有位置。

不要在源码克隆目录直接 `compose up`：它可能用相同项目名替换运行容器，却把相对路径 `./server-data` 指向新的空目录。无需重新上传基础镜像或覆盖运行目录里的 Compose/Caddy 配置，也不要执行 `docker compose down -v`。

v1.1 首次启动会创建录音／评分表并开启自动朗读一次。之后在设置里关闭会被记住。音频存于 `server-data/recordings/`，90 天后清除文件；学习 JSON 备份只含文字、评分与录音信息。恢复 v2 时只保留本服务器能核验的已有录音，另一台服务器恢复会显示音频缺失。旧版只认识 v1 备份，请保留升级前的完整数据备份用于回退。

## 回退

把保留的旧镜像重新标记为 `nihongo-web:local`，然后在 `/opt/nihongo` 重复上面的 app 更新命令。若变更涉及不兼容的数据结构，还需在停 app 后恢复对应的私密数据备份；仅回退镜像不能保证数据格式兼容。

恢复升级前数据会舍弃升级后的新记录。先另外保管当前完整 `server-data/`，再恢复旧备份。不要删除证书卷或改用仓库中的 Caddy 模板。

## 尚需在目标设备验证

自动化测试使用模拟语音和临时数据，不消耗 DeepSeek/MiniMax 额度。真实手机的播放、暂停/继续、录音权限，真实教材音频请求、云端 AI，以及本次版本在服务器上的运行情况，必须分别验收。构建通过和健康检查通过不代表这些项目已完成。本手册不会自动执行发布。
