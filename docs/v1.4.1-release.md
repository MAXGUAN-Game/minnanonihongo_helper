# v1.4.1 升级校验修复

修复 v1.4.0 升级时在 `check-progress-integrity.mjs` 报 `SQLITE_CANTOPEN: unable to open database file` 的问题。SQLite 的 WAL 数据库即使只读查询，也可能需要创建 WAL/SHM 辅助文件；原校验容器的数据库目录和根目录均只读，无法创建这些文件。

升级前后均停止应用写入，将数据库及存在的 WAL、回滚日志复制到容器临时目录，SQLite 仅打开副本并检查完整性。生产目录继续只读挂载。副本保留 WAL 中已提交的最新记录，退出后删除。比较历史数据摘要并验证认证成功后才恢复外部访问。

本版包含 v1.4.0 全部功能。截图中的失败发生在切换前，恢复日志表示旧应用及配置已恢复；请直接升级本版，无需恢复旧数据库备份。

## 服务器重试

从 [v1.4.1 发布页](https://github.com/MAXGUAN-Game/minnanonihongo_helper/releases/tag/v1.4.1) 下载 `nihongo-web-v1.4.1.tar.gz` 及 `nihongo-web-v1.4.1.tar.gz.sha256`，上传到服务器 `/tmp`。在服务器终端执行：

```bash
(
set -e
cd /tmp
sha256sum -c nihongo-web-v1.4.1.tar.gz.sha256
release_src=$(sudo mktemp -d /opt/nihongo-v141-src-XXXXXXXX)
sudo tar -xzf nihongo-web-v1.4.1.tar.gz -C "$release_src"
sudo systemd-run --unit="nihongo-update-v141-$(date +%s)" --collect \
  --service-type=exec --property=UMask=0077 \
  --property=TimeoutStopSec=300 \
  --property=StandardOutput=append:/opt/nihongo/update-v1.4.1.log \
  --property=StandardError=inherit \
  /usr/bin/bash "$release_src/deploy/update-session-release.sh" /opt/nihongo
)
```

查看日志：`sudo tail -n 50 -f /opt/nihongo/update-v1.4.1.log`。本次 `UPDATE_START v1.4.1` 后出现 `AUTH_VERIFIED v1.4.1` 和 `UPDATE_OK v1.4.1` 才表示成功；按 Ctrl+C 仅退出日志。

继续沿用原网站用户名、密码、HTTPS 及 AI 设置。不要把安装包解压到运行目录，不要恢复旧数据库覆盖现有进度。MiniMax 额度及真实长录音验收限制见 [v1.4.0 说明](v1.4.0-release.md)。

## 回归验证

- 数据库校验覆盖：干净关闭的 WAL 数据库、只存在主文件和 WAL（没有 SHM）、WAL 中最新提交记录、源文件逐字节不变、缺失/损坏数据库拒绝升级、临时副本清理。
- 升级流程覆盖：两次校验前均停写、认证通过后开放网关；校验失败、数据摘要不符或认证失败时恢复旧代码，保留当前学习数据。
- Linux 容器回归使用只读根目录与数据挂载复现旧错误，并验证临时副本方案。
