# v1.4.3 日语词组读音与断句候选修复

**试听未通过，暂勿部署。** 用户已试听原文＋词典的真实音频，并反馈仍有错误停顿。下面记录的是候选实现及原定发布步骤，不是已验证有效的断句修复。继续对比 MiniMax fluent 模式与本机 Haruka 声音，尚未选择通过听音验收的方案。

v1.4.2 将整句假名传给语音引擎，解决了传入文本中汉字读音不明确的问题，但没有验证语音模型的词组断句。用户继续反馈「午後二時四十分」在「に」「じ」之间出现不自然停顿，因此不能把 v1.4.2 的自动化通过等同于朗读质量修复完成。

本版给 MiniMax 同时传递原文与已有假名，使用官方 `pronunciation_dict.tone`。保留原句书写结构，将连续汉字、数字组成的词组整体指定读音：`午後二時四十分/ごごにじよんじゅっぷん`。不拆分时、分，也不把各词拼接成多个音频。只有原文与假名能够完整、唯一对齐时才生成规则；无法可靠对齐或同一字词出现冲突读音时，仍使用整句假名。系统语音不支持该词典，保持假名回退。

缓存同时区分原文、发音词典、音色、模型和速度。之前的纯汉字或纯假名音频不会被误当作本次词典音频。不修改学习数据库、词条 ID、课次和历史映射。

## 验证与限制

135 项相关自动化测试通过，包括两次用户反馈的时间表达、歧义对齐回退、缓存区分、整段对话、重播、隐藏假名和系统回退。真实 MiniMax `speech-2.8-hd` 已成功生成两段对照 WAV，使用 Japanese_KindLady、1.0 倍速，保存在本机 `public/pronunciation-preview/`，不进入部署包。

词典对照音频已被用户判定仍有错误停顿。发音词典不是强制禁止停顿的指令，不能仅凭合成成功或单元测试保证韵律自然。本版尚未在远端部署。

依据：[MiniMax 同步语音合成](https://platform.minimax.cn/docs/api-reference/speech-t2a-http)，发音词典支持日语假名；停顿标记用于插入停顿，并非消除模型自身断句，本版没有添加此类标记。

## 确认试听后更新

将 `releases/nihongo-web-v1.4.3.tar.gz` 和同名 `.sha256` 文件上传到服务器 `/tmp`，在已登录的阿里云终端执行：

```bash
(
set -e
cd /tmp
sha256sum -c nihongo-web-v1.4.3.tar.gz.sha256
release_src=$(sudo mktemp -d /opt/nihongo-v143-src-XXXXXXXX)
sudo tar -xzf nihongo-web-v1.4.3.tar.gz -C "$release_src"
sudo systemd-run --unit="nihongo-update-v143-$(date +%s)" --collect \
  --service-type=exec --property=UMask=0077 \
  --property=TimeoutStopSec=300 \
  --property=StandardOutput=append:/opt/nihongo/update-v1.4.3.log \
  --property=StandardError=inherit \
  /usr/bin/bash "$release_src/deploy/update-session-release.sh" /opt/nihongo
sudo tail -n 60 -f /opt/nihongo/update-v1.4.3.log
)
```

脚本沿用先构建、暂停写入、备份远端数据库和 WAL、配置及保留旧镜像、核对历史摘要与认证、恢复访问的流程，保留 HTTPS 和凭据。以本次日志的 `AUTH_VERIFIED v1.4.3` 和 `UPDATE_OK v1.4.3` 为完成标记，再刷新页面登录并检查历史进度、实际题目音频。不能恢复旧数据快照覆盖新增进度。
